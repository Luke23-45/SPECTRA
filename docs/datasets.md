# Datasets

This document records what each dataset in SPECTRA is, where it comes from, how it is materialized inside this repository, and which file defines the corresponding training configuration. The intent is to make the data story auditable from the paper to the code.

## Scope

SPECTRA uses two distinct kinds of data:

- Real or externally sourced benchmarks used by the standard training entry point in `scripts/run_training.py`.
- Synthetic benchmarks generated inside this repository for controlled empirical stress testing through `scripts/run_empirical_experiment.py`.

The standard training configs are defined under `configs/dataset/`. The empirical synthetic benchmark configs are defined under `configs/empirical/`.

## Standard Training Datasets

| Dataset | Role in repository | Source acquisition path | Local config |
|--------|---------------------|--------------------------|--------------|
| Synthetic | Fast local training benchmark | Generated in-process by `spectra/data/synthetic.py` | `configs/dataset/synthetic.yaml` |
| NYUv2 | Dense prediction benchmark | Downloaded from the Hugging Face dataset `tanganke/nyuv2`, then materialized to LMDB | `configs/dataset/nyuv2.yaml` |
| Yeast | Multi-label classification benchmark | Downloaded as ARFF train/test splits from the MEKA dataset mirror | `configs/dataset/yeast.yaml` |
| RF1 | Multi-target regression benchmark | Downloaded as ARFF train/test splits from the Mulan dataset mirror | `configs/dataset/rf1.yaml` |
| QM9 | Molecular regression benchmark | Downloaded from the Hugging Face mirror `n0w0f/qm9-csv`, then featurized in-repo | `configs/dataset/qm9.yaml` |
| Clinical | Clinical ICU time-series benchmark | Resolved from local files, a configured Hugging Face dataset snapshot, or a local build pipeline | `configs/dataset/clinical.yaml` |

## Standard Dataset Details

### Synthetic

The standard training synthetic dataset is not downloaded. It is generated at runtime by `spectra/data/synthetic.py` and wrapped by `spectra.data.datamodule.SPECTRADataModule` in `spectra/data/datamodule.py`.

What it actually is:

- Inputs are sampled from a Gaussian feature space.
- Targets are generated by applying fixed random mappings to a shared latent representation.
- The default task set contains 7 tasks: 4 regression tasks and 3 binary classification tasks.
- The default training config is `configs/dataset/synthetic.yaml`.

Files that define this path:

- `configs/dataset/synthetic.yaml`
- `spectra/data/synthetic.py`
- `spectra/data/datamodule.py`

This synthetic dataset is a training convenience benchmark. It is not the same system as the paper's empirical stress-test suite described later in this document.

### NYUv2

The NYUv2 path in this repository is a three-task dense prediction benchmark with segmentation, depth, and surface-normal targets. The repository does not ship the raw dataset. Instead, it downloads a Hugging Face-hosted copy and converts it into an LMDB layout used by the runtime loader.

What the repository does:

- `spectra/data/nyuv2/nyuv2_lmdb_sota.py` downloads `tanganke/nyuv2` with `datasets.load_dataset(..., streaming=True)`.
- The pipeline writes per-split LMDB files and JSON index manifests under `datasets/nyuv2_lmdb/`.
- `spectra/data/nyuv2/dataset.py` reads the LMDB materialization and exposes three targets:
  - segmentation
  - depth
  - normals
- The training config in `configs/dataset/nyuv2.yaml` defines the benchmark name, root path, image shape, class count, and optimization defaults.

Repository-defined assumptions that matter for the paper:

- The configured benchmark uses 13 semantic classes.
- The config records `train_size: 795` and `val_size: 654`.
- The loader expects the preprocessed LMDB layout, not the original raw NYUv2 release layout.

Files that define this path:

- `configs/dataset/nyuv2.yaml`
- `scripts/data/nyuv2_generate.py`
- `spectra/data/nyuv2/nyuv2_lmdb_sota.py`
- `spectra/data/nyuv2/dataset.py`
- `spectra/data/datamodule.py`

### Yeast

The Yeast benchmark is materialized from ARFF files downloaded from the MEKA train/test split mirror. The repository treats the source train split as SPECTRA `train` and the source test split as SPECTRA `val`.

What the repository does:

- `spectra/data/yeast/ingest.py` downloads `yeast-train.arff` and `yeast-test.arff`.
- It parses the ARFF schema, splits features from the final 14 label columns, checks that labels are binary, computes normalization statistics on the training features, and writes compressed `.npz` split files.
- `spectra/data/yeast/dataset.py` loads the prepared files.
- `configs/dataset/yeast.yaml` defines the model-facing view: `input_dim: 103`, `num_labels: 14`, and the 14 binary tasks used by training.

Files that define this path:

- `configs/dataset/yeast.yaml`
- `scripts/data/yeast_generate.py`
- `spectra/data/yeast/ingest.py`
- `spectra/data/yeast/dataset.py`
- `spectra/data/datamodule.py`

### RF1

The RF1 benchmark is materialized from ARFF files downloaded from the public Mulan multi-target regression mirror. The repository maps the benchmark's source `train` and `test` splits onto SPECTRA `train` and `val`.

What the repository does:

- `spectra/data/rf1/ingest.py` downloads `rf1-train.arff` and `rf1-test.arff`.
- Missing input values are imputed with training-column means computed inside the ingestion pipeline.
- The ingest stage writes compressed `.npz` splits and `metadata.json`.
- `configs/dataset/rf1.yaml` defines the model-facing task set of 8 regression targets.

Files that define this path:

- `configs/dataset/rf1.yaml`
- `scripts/data/rf1_generate.py`
- `spectra/data/rf1/ingest.py`
- `spectra/data/rf1/dataset.py`
- `spectra/data/datamodule.py`

### QM9

The QM9 path used by this repository is not a raw molecular graph pipeline. It uses a CSV mirror and constructs deterministic tabular features from SMILES and InChI strings.

What the repository does:

- `spectra/data/qm9/ingest.py` downloads a CSV from the Hugging Face mirror `n0w0f/qm9-csv`.
- The pipeline derives feature columns from parsed formula counts and string-level SMILES statistics.
- The train/validation split is created inside the repository with a seeded random split:
  - `SPLIT_SEED = 42`
  - `TRAIN_FRAC = 0.9`
- `configs/dataset/qm9.yaml` defines the resulting 12 regression targets used for training.

This means the repository uses a reproducible tabularized QM9 representation, not a graph neural network representation.

Files that define this path:

- `configs/dataset/qm9.yaml`
- `scripts/data/qm9_generate.py`
- `spectra/data/qm9/ingest.py`
- `spectra/data/qm9/dataset.py`
- `spectra/data/datamodule.py`

### Clinical

The clinical benchmark is handled differently from the other datasets. The repository supports three acquisition tiers through `ensure_data_ready(...)` in `spectra/data/clinical/dataset.py`:

- existing local prepared data
- a configured Hugging Face dataset snapshot
- a local build pipeline via `spectra/data/clinical/dataset_quality.py`

What the repository does:

- `configs/dataset/clinical.yaml` defines the training-facing benchmark contract, including `dataset_dir` and `hf_repo`.
- `spectra/data/clinical/dataset.py` validates the expected 28-channel ICU schema and exposes two prediction targets:
  - `outcome`
  - `phase`
- The data loader uses LMDB-based prepared splits and supports sepsis-aware sampling.

The docs should not claim a single public upstream source for this benchmark, because the repository itself supports multiple acquisition modes.

Files that define this path:

- `configs/dataset/clinical.yaml`
- `spectra/data/clinical/dataset.py`
- `spectra/data/clinical/dataset_quality.py`
- `spectra/data/datamodule.py`

## Preparation Commands

Repository-level wrappers exist for the externally sourced datasets that require a materialization step:

```bash
python scripts/data/nyuv2_generate.py
python scripts/data/yeast_generate.py
python scripts/data/rf1_generate.py
python scripts/data/qm9_generate.py
```

The underlying implementations live in:

- `spectra/data/nyuv2/nyuv2_lmdb_sota.py`
- `spectra/data/yeast/ingest.py`
- `spectra/data/rf1/ingest.py`
- `spectra/data/qm9/ingest.py`

Clinical data preparation is handled indirectly through the loader entrypoint:

- `spectra/data/clinical/dataset.py`
- `spectra/data/clinical/dataset_quality.py`

## Expected On-Disk Layout

After preparation, the standard training datasets are expected under `datasets/`:

```text
datasets/
|-- nyuv2_lmdb/
|-- yeast/
|-- rf1/
|-- qm9/
`-- sepsis_clinical_28/   # if the configured clinical dataset is present locally
```

The exact runtime root for each dataset is defined in its corresponding config file under `configs/dataset/`.

## Empirical Synthetic Benchmark Suite

The paper's controlled synthetic experiments do not use `spectra/data/synthetic.py`. They use a separate benchmark framework under `spectra/empirical/`.

The entrypoint is:

- `scripts/run_empirical_experiment.py`

The benchmark configuration root is:

- `configs/empirical/`

The synthetic problem abstraction is defined in:

- `spectra/empirical/generators/base.py`

The implemented synthetic families are:

- `correlation`: controlled task alignment in `spectra/empirical/generators/correlation_family.py`
- `conflict`: aligned, opposed, and orthogonal task structure in `spectra/empirical/generators/conflict_family.py`
- `imbalance`: controlled scale and class-prior imbalance in `spectra/empirical/generators/imbalance_family.py`
- `rescaling`: fixed target bundle with training-time loss rescaling in `spectra/empirical/generators/rescaling_family.py`
- `heterogeneous`: mixed losses and task types in `spectra/empirical/generators/heterogeneous_family.py`

The default experiment configs that select these families are:

- `configs/empirical/experiment/exp_01_correlation_sweep.yaml`
- `configs/empirical/experiment/exp_02_conflict_stability.yaml`
- `configs/empirical/experiment/exp_03_imbalance_robustness.yaml`
- `configs/empirical/experiment/exp_04_control_benign.yaml`
- `configs/empirical/experiment/exp_05_multiclass_behavior.yaml`
- `configs/empirical/experiment/exp_06_orchestrator.yaml`
- `configs/empirical/experiment/exp_07_pure_loss_rescaling.yaml`
- `configs/empirical/experiment/exp_08_heterogeneous_regime.yaml`

The study runner uses these empirical experiments for the stress studies:

- `02_synthetic_scale_stress` via `experiments/bpgs_study/stress/configs/02_synthetic_scale_stress.yaml`
- `06_pure_loss_rescaling` via `experiments/bpgs_study/stress/configs/06_pure_loss_rescaling.yaml`
- `07_heterogeneous_mixed_stress` via `experiments/bpgs_study/stress/configs/07_heterogeneous_mixed_stress.yaml`

This distinction matters for the paper:

- `configs/dataset/synthetic.yaml` defines the standard training synthetic benchmark.
- `configs/empirical/` plus `spectra/empirical/generators/` define the controlled stress-test benchmark suite.

They are related only in the broad sense that both are synthetic. They are not the same dataset path.

## Example Dataset Selection Commands

Examples for the standard training entrypoint:

```bash
python scripts/run_training.py dataset=yeast method=bpgs seed=42
python scripts/run_training.py dataset=rf1 method=kendall seed=42
python scripts/run_training.py dataset=qm9 method=static seed=42
python scripts/run_training.py dataset=clinical method=bpgs seed=42
python scripts/run_training.py preset=nyuv2_bpgs seed=42
```

Example for the empirical benchmark entrypoint:

```bash
python scripts/run_empirical_experiment.py experiment=exp_03_imbalance_robustness
```
